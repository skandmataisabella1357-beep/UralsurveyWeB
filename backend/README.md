# Служба управления на Python и PostgreSQL

Панель администратора и всё, что за ней: станции, точки подключения, клиенты, логины NTRIP,
тарифы, подписки, журналы сеансов и отказов, журнал действий, настройки, роли.
Приём и раздача потоков остаются на Node.js (`server/ingest`, `server/caster`): из базы они
берут только справочник и складывают в неё журнал сеансов.

## Состав

| Файл | Что в нём |
|---|---|
| `migrations/001_init.sql` | Схема базы |
| `uralsurvey_admin/db.py` | Подключение и применение схемы |
| `uralsurvey_admin/security.py` | Хеши паролей, токены, шифрование паролей NTRIP ключом сервера |
| `uralsurvey_admin/store.py` | Все операции администратора: проверка данных и работа с базой |
| `uralsurvey_admin/api.py` | HTTP: панель, справочник для служб, приём журнала сеансов |
| `tests/test_admin.py` | Тесты на настоящем PostgreSQL |

## Запуск

```
python -m venv venv && venv/bin/pip install -r backend/requirements.txt
cd backend
URAL_DSN="dbname=uralsurvey" ../venv/bin/python -m uralsurvey_admin migrate
../venv/bin/python -m uralsurvey_admin create-admin ЛОГИН      # пароль вводится с клавиатуры
../venv/bin/python -m uralsurvey_admin serve
```

Переменные: `URAL_DSN` (база), `URAL_HOST`, `URAL_PORT` (страница), `URAL_INGEST`, `URAL_CASTER`
(адреса состояния служб), `URAL_DATA` (папка с ключами `secret.key` и `internal.key`).

## Роли

- **Администратор** — всё.
- **Оператор** — смотрит, закрывает сеансы, выдаёт пробный доступ. Станции, точки, тарифы,
  логины, настройки и журнал действий не меняет и паролей не видит.

## Что где хранится

- Пароли администраторов — только хешем (scrypt).
- Пароли NTRIP и пароли источников — зашифрованы ключом `secret.key`, который лежит отдельно от базы.
- Токены сеансов панели — в базе только их хеш.
- Журнал действий только дополняется: правку и удаление запрещает сама база.

## Тесты

```
URAL_TEST_DSN="host=/путь/к/сокету port=54329 user=test dbname=postgres" \
  python -m unittest discover -s backend/tests
```

Каждый прогон создаёт свою базу и удаляет её в конце.

## Как службы приёма и раздачи связаны с базой

Раз в три секунды они спрашивают у службы управления справочник (`/internal/directory`):
станции с источниками, точки подключения, логины с правами. Изменения применяются на ходу:
новая станция заводится, изменённая перезапускается, остальные работают без перерыва;
сеансы отключённого логина или удалённой точки закрываются. Раздача шлёт обратно сеансы
и отказы (`/internal/events`). Эти адреса доступны только с самой машины и по ключу
`internal.key`; запрос, пришедший через nginx, не принимается.

Если служба управления или база недоступны, приём и раздача работают по последней полученной
копии справочника, а события ждут в очереди.

## На сервере

```
cd /opt/uralsurvey-web/backend
export URAL_CONFIG=/opt/uralsurvey-web/data/config.json
../venv/bin/python -m uralsurvey_admin create-admin ЛОГИН          # администратор
../venv/bin/python -m uralsurvey_admin create-admin ЛОГИН --operator
```
