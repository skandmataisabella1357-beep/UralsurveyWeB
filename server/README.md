# Сервер Uralsurvey

Каркас сервера раздачи NTRIP. ТЗ — `docs/tz-ntrip-server.md` (на согласовании),
порядок работ — `docs/claude-code-task-server.md`.

## Запуск на своём компьютере

```
npm run server
```

Поднимаются три службы и страница состояния: http://127.0.0.1:8080/

Без файла `server/config.json` сервер берёт образец `config.example.json` и работает
на трёх имитаторах станций — настоящая сеть при этом не затрагивается.

## Службы

| Папка | Служба | Что делает сейчас |
|---|---|---|
| `ingest/` | Приём | Держит соединения со станциями через общее ядро `core/`, отдаёт потоки по внутренней шине |
| `caster/` | Раздача | NTRIP версий 1 и 2: таблица источников, проверка логина, правила сеанса из ТЗ, подготовка потока |
| `rtcm/` | Кодирование | Служебные сообщения RTCM и замена номера станции в кадре |
| `testnet/` | Тестовая сеть | 50 синтетических баз с неисправностями связи: `npm run testnet` |
| `control/` | Управление | Собирает состояние служб, отдаёт страницу и `/api/state` |
| `web/` | Страница | Состояние служб и станций в браузере |
| `shared/` | Общее | Шина между службами, чтение настроек, служебный HTTP |

Каждая служба запускается и отдельно: `node server/ingest/index.js` и так далее.
Все они слушают только `127.0.0.1`: наружу сервер не открыт.

## Настройки

- `config.json` — всё, что не секрет: порты, список станций и их источники. Образец — `config.example.json`.
- `secrets.json` — логины и пароли источников. Образец — `secrets.example.json`.
- Оба файла в git не попадают.

Источник станции (`source.mode`):

| Режим | Поля | Когда |
|---|---|---|
| `sim` | `lat`, `lon`, `h`, `stationId` | Имитатор, для проверки сервера |
| `ntrip` | `host`, `port`, `mountpoint`, `credentials` | Поток с действующего кастера; `credentials` — имя записи в `secrets.json` |
| `tcp` | `host`, `port` | Открытый порт приёмника |
| `listen` | `port`, `allow` | Приёмник сам шлёт поток на сервер, на свой порт |

Пример станции с настоящего кастера:

```json
{ "code": "REFT", "name": "Рефтинский", "source": { "mode": "ntrip", "host": "адрес", "port": 2101, "mountpoint": "REFT_MSM4", "credentials": "кастер" } }
```

## Панель администратора

Страница `/admin.html` службы управления, за входом. Разделы плитками: обзор, станции (карта, таблица,
карточка станции с координатами в X, Y, Z), точки подключения, сеансы роверов, отказы.
Панель пока только показывает состояние; правка через неё — следующий шаг.

Пароль администратора задаёт владелец сервера, с клавиатуры:

```
npm run set-admin
```

В файл `data/admin.json` (вне git) попадает только хеш. На сервере rtk.ntrip.host это
`/opt/uralsurvey-web/data/admin.json`. Пока пароль не задан, панель закрыта. Открытая страница `/`
и `/api/state` показывают только службы и станции — без адресов источников, журналов и роверов.

## Защита приёма

Для баз, которые сами шлют поток (`listen`), перед ядром стоит шлюз `ingest/gate.js`:

- `source.allow` — список разрешённых адресов станции: `["1.2.3.4", "10.0.0.0/8"]`. Пустой — любые адреса.
- пароль станции — в `secrets.json`: `{ "stationPasswords": { "REFT": "…" } }`. С паролем база обязана
  представиться как NTRIP-сервер (`SOURCE пароль /REFT` или `POST /REFT` с Basic); голый поток не принимается.
- живое соединение молчащим не заменяется: новое подключение ждёт в запасе и занимает место, только когда
  действующее замолчало на 3 с, а новое уже прислало целый кадр RTCM.
- `ingest.publicBind` и `caster.publicBind` — адрес для портов станций и порта роверов; внутренние порты
  служб остаются на `bind`.

## Раздача

Точки подключения — список `mountpoints` в `config.json`: `{ "name", "station", "stationId", "listed", "enabled", "access" }`.
Без списка заводится по точке на станцию с именем, равным её коду.

Логины роверов — в `secrets.json`:

```json
{ "users": { "логин": { "password": "…", "maxSessions": 1, "onLimit": "evict", "mountpoints": ["REFT"], "active": true, "expires": "2027-01-01" } } }
```

`caster.openAccess: true` пускает без логина и работает только на адресе `127.0.0.1` — для проверки на своём компьютере.

## Расчёт подсетей

Служба `server/solver/index.js` (состояние — порт 7104) считает координаты станций подсети от
опорной станции по живым потокам. Задания берёт у службы управления, потоки — с внутренней шины,
векторы считает RTKLIB из папки `data/rtklib` (или `URAL_RTKLIB`), эфемериды — из открытого архива
BKG. Рабочие файлы — в `data/solver/НОМЕР_ПОДСЕТИ`, после остановки расчёта удаляются. Подробности —
в `CLAUDE.md`, раздел «Подсети и расчёт координат».

## Тестовая сеть

```
npm run testnet                      # сервер и 50 баз на своём компьютере
npm run testnet -- --target АДРЕС    # только базы: поток уходит на сервер по портам 2110–2159
npm run testnet -- --config          # настройки сервера под эту сеть
```
